# Adoption guide

1. Identify the existing project and audit the actual public repository separately from its development workspace.
2. Establish a rights-cleared distribution boundary. Do not copy the reference project's code or data to create an appearance of technical depth.
3. Copy only these documentation templates. Replace placeholders using verified project evidence.
4. Write domain-specific questions, methods, assumptions and validation criteria.
5. Record contributions and AI use with honest uncertainty.
6. Add a bounded demonstration only if an already approved module and safe inputs support it.
7. Check links, citation metadata, source integrity, privacy and rights. Record what did not run.
8. Prepare a local candidate and require researcher approval before publication.

Use the expanded [AI contribution matrix](AI_DISCLOSURE_TEMPLATE.md) and [evidence/runtime requirements](SCIENTIFIC_EVIDENCE_MATRIX.md). Establish your own researcher confirmations rather than copying IBCE's. Supply independent numerical reference code and exact reproducibility records where justified; preserve historical reports without upgrading them. Audit asset provenance, metadata and redistribution rights, with unresolved rights blocking publication. Confirm author/name fields against the project's actual release metadata, not its portfolio documentation version. Follow the explicit [publication gate](PUBLICATION_CHECKLIST.md) for the exact diff, settings and workflow actions.

## Domain adaptation

| Domain | Project-specific evidence to establish |
|---|---|
| Computational biology / bioinformatics | Cohort, identifiers, preprocessing, units, multiplicity and biological interpretation |
| Molecular modeling | Structures, force fields, docking/model assumptions and experimental comparison |
| Scientific visualization | Data lineage, transformations, uncertainty and faithful encodings |
| Research databases | Provenance, update policy, access boundaries and data rights |
| Statistical software | Numerical references, assumptions, tolerances and failure conditions |
| Biological digital twins | Calibration, parameter identifiability, simulation scope and external validation |
| Educational research | Learning objectives, consent, measurement validity and actual evaluation design |

These are prompts for review, not capabilities to claim. Never inherit IBCE's breast-cancer context, tests, validation results, licenses, manuscript status or methodological choices by adopting the standard.
