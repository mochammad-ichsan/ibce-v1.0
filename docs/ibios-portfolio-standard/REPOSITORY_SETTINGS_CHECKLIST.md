# Repository settings checklist

Record current values using read-only access; if unavailable, say not inspected. Propose changes without applying them.

| Setting | Required decision |
|---|---|
| Description | Concise verified function; no promotional maturity claim |
| Homepage | Verified live application or academic page; never guessed |
| Topics | Match actual methods and project purpose |
| Visibility / ownership / name | Preserve unless separately authorized |
| Branch rules | Review and approval policy appropriate to collaborators |
| Actions | Read-only permissions, no secrets/private services, no deployment |
| Secret scanning | Inspect availability; do not claim it is enabled without evidence |
| Issues / discussions | Do not enable contribution or disclosure channels automatically |
| Citation / license | Confirm authorship and rights; preserve existing license |
| Release / publication | Explicit approval of exact candidate and external action |

Do not copy credentials, identities, deployment settings or licensing assumptions from the reference project.

Record the major runtime promised by CI and the exact runtime/dependencies actually tested. Pin third-party actions to reviewed immutable commits, keep permissions minimal and credentials unpersisted, and require separate explicit workflow publication/activation approval. A prepared workflow is not an executed or green workflow.
